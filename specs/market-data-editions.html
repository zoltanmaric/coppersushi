Which price could we use at 11:00?

Collect every publisher independently. Preserve what arrived, when it arrived, and when it passed validation. Critical Elements ⚡️ and forecasting can then reconstruct a decision from the same archive.

From publisher to decision

  1. Lambda polls each publisher. Fetch ENTSO-E, Electricity Maps, SMARD and JAO independently. Success from one never suppresses another. Tune schedules to publication windows, the consumer deadline and each publisher’s rate limits. Isolate failures and cooldowns by publisher.
  2. S3 preserves evidence. Give each poll an identity. Record publisher, dataset, request scope, outcome and completion time. Save the response and receipt time even for partial or malformed data. A timeout has an attempt record. Keep licensed payloads private and credentials out of diagnostics. Repeated polls can reference one content-addressed body.
  3. Pandera validates editions for Parquet. Store published prices and signed border spreads in separate typed tables. Key versions by publisher, auction, zone or border, delivery interval and edition. Preserve units, upstream attribution and links to receipts. Write immutable objects, then publish their manifest last. Readers skip incomplete writes.
  4. A shared reader selects by cutoff. Read only stored editions usable by the requested instant. For eligible direct prices prefer ENTSO-E, with SMARD and Electricity Maps as alternates. Require matching auction, zone, interval and unit. Surface conflicting values with both receipts. Record the selection policy version and chosen evidence in the decision manifest.
Which component owns each clock?

Use timezone-aware UTC columns. A weather forecast records its cycle and valid time. An auction price records its delivery interval. Preserve publisher update or publication time only with its documented meaning. Collectors witness receipt. Validation records when a version became usable for a named contract. Reprocessing an old body must preserve the original validation history. An issued forecast separately records issue time, first observed customer availability, and the pinned inputs, model and code.

What can callers accept?

A published price points to its publisher and receipt. A derived price points to an eligible absolute price in another zone and every signed JAO spread connecting it to the target, all for the same quarter. If no anchor exists, return the missing interval and attempted sources. Reject inconsistent paths. Derivation time cannot establish earlier input availability.

Critical Elements ⚡️ can require a complete regional table and accept derived quarters. Forecast issuance can accept a derived input when its policy allows it and all evidence was usable by the deadline. Evaluation pins its outcome snapshot. Source audits can inspect each publisher separately.

Build and verify in slices

  1. Prove the clocks. Poll ENTSO-E and Electricity Maps for one DE–LU delivery window using the AWS collection path. Demonstrate the timeline above through the normal archive reader with network access disabled during replay. Show both attempts when one publisher fails.
  2. Prove durable identity. Retry an interrupted write, repeat an identical poll, then ingest a correction. Verify one receipt per distinct attempt, stable body references, no half-published edition, and identical historical selections.
  3. Prove recovery. Add SMARD prices and JAO spreads. Exercise a missing direct quarter, missing anchor, conflicting direct observations and a spread first received after cutoff. Verify values, failure reasons and evidence references.
  4. Switch consumers. Run the same archived day through Critical Elements ⚡️ and forecast issuance. Trace each selected price to its evidence. Reproduce the frozen evaluation with its original snapshot.

Start with schemas and manifests as the inventory. Add a queryable catalog when finding publisher coverage or editions becomes a measured problem. A database, feature store and changes to model fitting are outside the first slice.

Existing foundations

The merged forecast pipeline already uses typed input versions and frozen S3 snapshots. The collection cadence, shared archive reader and usability receipts above are proposed work. The earlier prototype supplies a tested Electricity Maps reader, comparison cases, and evidence-preservation and naming rules to recover selectively.
