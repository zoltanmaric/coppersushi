COPPER SUSHI / FORECASTSDESIGN REVIEW

GERMANY–LUXEMBOURG · OPERATIONS

One fit per month.
One issue per day.

An authorized reader can retrieve tomorrow’s complete forecast by Berlin delivery date with the laptop off.

Follow a delivery day

  1. Freeze the month. On the last Berlin day of each month at or after 11:00, a monthly workflow runs the existing archive-backed monthly_fit command. Supply the approved configuration, verified snapshot and exact archive coverage policy. Publish its entire checked bundle under its identity. Create fits/YYYY-MM.json last with a conditional S3 write. Include bundle versions, hashes, fit cutoff, image digest and workflow execution.
  2. Issue for the delivery month. Derive tomorrow from the scheduled Berlin business date, including on delayed retries. The daily workflow fetches the exact monthly pointer and verifies the bundle. On rollover wait within the delivery budget for training. A missing or invalid pointer fails the issue. Pass that bundle to forecasts.daily. Preserve both methods, all input evidence and the existing JSON layout.
  3. Read by date. An authenticated reader gets issues/YYYY-MM-DD.json from private S3 and validates the day, methods, quantiles, interval grid, input policy and fit receipt. Conditional creation gives concurrent triggers one winner. The losing attempt checks the winning identity. A separate reader role records the first validated GET time and object version. Keep historical replays in a separate prefix.

Two clocks on the preceding day

11:00 Europe/Berlin fixes the latest eligible information. Live selection uses the earlier of actual selection time and cutoff. Ask for the required availability time during implementation. For a later SLA, extend the existing command and validator with an explicit publication deadline, retaining the local default and existing fields. Independently enforce the 11:00 cap on each receipt. Use S3 GET evidence for remote availability. A copied file’s inode time cannot establish remote delivery. If the deadline leaves insufficient time for the first fit, resolve that with the operator before activation.

Execution and recovery

Terraform owns private storage, ECR, roles, Fargate Batch queue, logging and Berlin EventBridge Scheduler triggers. Metaflow generates the Step Functions definitions. Use the locked Linux x86 runtime and immutable image digest across steps. Ship committed sources and verifiable Git revision for both commands. Start with public subnets, task-only public IPs, no inbound rules, and scale to zero. Preserve the existing shared archive. Deploy schedules disabled.

Keep attempt diagnostics by date and execution ID, including failures before the scientific command runs. Trace scheduler invocation → Step Functions execution → Batch job/log → source receipts and affected quarters. Check for the expected reader receipt by the agreed time even if Scheduler never started a workflow. Retry the original business date and pins, preserving failures. A late recovery is explicitly historical. Keep fit and issue authority immutable.

Prove the handoff

  1. Freeze the known local November 24 reconstruction, its original prices-only configuration and snapshot 201a814795595ab02a66140bcacb72fa47cd52605e06358975caf4dc017c2480. Save object versions and SHA-256 before launching. Refit November on AWS from the matching frozen inputs. The second AWS execution must resolve that first execution’s published bundle. Compare the fit manifest and model hashes through the entire path.
  2. Use the registered reproduction tolerance from run-config.json, absolute 0.000001 €/MWh plus relative 0.000000001 times the absolute local value. Require finite values, exact dated UTC grid, exact column order and five values per method. Compare the reader’s returned forecast against the frozen local oracle. Reject a changed reference tail, missing quarter, wrong fit or missing object. Also exercise 92- and 100-quarter days.
  3. Capture billed task duration including image pull, wall time, cgroup peak memory, revision, image digest, bundle ID, model hashes and input versions. Size each task with measured headroom. Test a missing required price in an isolated replay and check the operator view for cause and date. Trigger two concurrent runs and verify exactly one authoritative version. Finally witness a real scheduled live edition, correct inputs, both methods and a validated read before the agreed deadline.

Monthly budget

Illustrative incremental budget in Ireland, USD before tax and credits. Assume Linux x86 at rounded planning rates of $0.05/vCPU-hour and $0.006/GB-hour. One 2-vCPU, 8 GB fit for 60 minutes costs $0.15. Thirty-one 1-vCPU, 2 GB issues at ten minutes cost $0.32. Allow another $0.15 for short workflow steps and task IPs. Allow $0.50 for transitions, scheduler, logs, monitoring and requests. Idle storage of 5 GB in ECR and 10 GB in S3 adds about $0.73/month. Total about $1.85/month at those volumes. Excludes the existing market archive, tax and external transfers. No NAT gateway, load balancer, database or always-on compute in this estimate. Validate the pinned Metaflow backend and actual service inventory before apply. Reprice from job measurements, archive request counts and retained bytes.
