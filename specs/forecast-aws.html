COPPER SUSHI / FORECASTSAPPROVED DESIGN

GERMANY–LUXEMBOURG · OPERATIONS

One fit per month.
One issue per day.

An authorized reader can retrieve tomorrow’s complete forecast by Berlin delivery date with the laptop off.

Follow a delivery day

  1. Freeze the month. On the last Berlin day of each month at or after 11:00, a monthly workflow runs the existing archive-backed monthly_fit command. Supply the approved configuration, verified snapshot and exact archive coverage policy. Publish its entire checked bundle under its identity. Create fits/YYYY-MM.json last with a conditional S3 write. Include bundle versions, hashes, fit cutoff, image digest and workflow execution.
  2. Issue for the delivery month. Derive tomorrow from the scheduled Berlin business date, including on delayed retries. The daily workflow fetches the exact monthly pointer and verifies the bundle. On rollover wait within the delivery budget for training. A missing or invalid pointer fails the issue. Pass that bundle to forecasts.daily. Preserve both methods, all input evidence and the existing JSON layout.
  3. Read by date. An authenticated reader gets issues/YYYY-MM-DD.json from private S3 and validates the day, methods, quantiles, interval grid, input policy and fit receipt. Conditional creation gives concurrent triggers one winner. The losing attempt checks the winning identity. A separate reader role records the first validated GET time and object version. A live edition is authoritative only with the matching conditional first-read receipt, whose timestamp follows complete validated GET and must meet the SLA. A post-deadline publication or first GET leaves a missed issue and its evidence. All readers enforce this pairing. Keep historical replays in a separate prefix.

Two clocks on the preceding day

11:00 Europe/Berlin fixes the latest eligible information. Live selection uses the earlier of actual selection time and cutoff. Ask for the required availability time during implementation. For a later SLA, extend the existing command and validator with an explicit publication deadline, retaining the local default and existing fields. Independently enforce the 11:00 cap on each receipt. Use S3 GET evidence for remote availability. A copied file’s inode time cannot establish remote delivery. If the deadline leaves insufficient time for the first fit, resolve that with the operator before activation.

Execution and recovery

Terraform owns private storage, ECR, roles, Fargate Batch queue, logging and Berlin EventBridge Scheduler triggers. Metaflow 2.19.39 generates two linear Step Functions workflows with local task metadata and S3 storage. Linear flows avoid the foreach DynamoDB dependency. Smoke-test task metadata offload and Batch startup. Use the locked Linux x86 runtime and immutable image digest across steps. Ship committed sources and verifiable Git revision for both commands. Start with public subnets, task-only public IPs, no inbound rules, and scale to zero. Preserve the existing shared archive. Deploy schedules disabled.

Keep attempt diagnostics by date and execution ID, including failures before the scientific command runs. Trace scheduler invocation → Step Functions execution → Batch job/log → source receipts and affected quarters. Check for the expected reader receipt by the agreed time even if Scheduler never started a workflow. Retry the original business date and pins, preserving failures. A late recovery is explicitly historical. Keep fit and issue authority immutable.

Monthly budget after measurement

Allow about $0.82 per month in Ireland, before tax or credits. This assumes one CPU fit, 31 issues, 31 independent deadline checks, two Batch tasks per workflow, and no retries. The snapshot replay took about 2½ minutes from the first submitted job to the end of its reader. Image pull to task stop was 61.4 s for its issuer and 58.2 s for its reader. Budget 70 s per daily task, including the Fargate one-minute minimum, and five minutes for the monthly workflow. At the Ireland Linux x86 rates of $0.04048/vCPU-hour and $0.004445/GB-hour, task compute and temporary public IPs cost about $0.14.

Idle storage budget is $0.40 for up to 1.7 GB of images and 10 GB of retained versioned S3 data. The first release image was 545 MB compressed. Allow $0.20 for CloudWatch ingestion and retention, $0.05 for 5,000 writes/lists and 50,000 reads, and $0.03 for up to 1,000 Step Functions transitions and Scheduler invocations. Rounded allowances total $0.82. Actual cost grows with retained artifacts, request volume and rollover wait time. The existing archive and external downloads are outside this incremental budget. Compute scales to zero; the deployment has no NAT gateway, endpoints, load balancer or database.
