Reviewable contracts

UI and routes

/polish-export-caps uses the existing navigation unchanged. /embed/polish-export-caps/breakdown shows the graphic and caveat; /embed/polish-export-caps/intervals shows the native map and table. Both reuse the same React components as the full page, with no navigation in embeds.

The table has one binding quarter-hour per row: combined date/time link; shadow price (€/MWh); required, procured and signed shortfall (MW); export cap (MW); Polish day-ahead price (€/MWh). Every column sorts and filters. Numeric columns get inclusive min/max filters; date/time gets an inclusive delivery-date range using the existing DayPicker calendar styling, with clearable endpoints. Default: shadow price descending, UTC timestamp ascending to break ties. Show result count, reset, selected row, empty and error states. Scroll all matching rows independently, with sticky column headers and filters. Size the map and table together to keep the map visible; no pagination.

Initial map selection is the highest-shadow-price row, reference PL, constraint cap:PL. Clicking a timestamp selects it without remounting the map; the link also works in a new tab. Map controls update the same state; a nonbinding map interval has no table highlight. Filtering out the selected interval retains the map and labels the selection as outside the results. The graphic always describes the full study window; filters affect only the table.

URL state and map continuity

One validated route model owns from, to, numeric {column}Min/Max, sort, order, selected day/interval, reference, constraint, and camera lat/lon/zoom. Canonical serialization omits defaults. Invalid supplied values show a recoverable message; they do not silently change meaning. Clear removes the relevant parameters.

Use the published market-day interval index to distinguish repeated DST times; show Europe/Brussels date, time and CET/CEST. Replace history for view changes, consistent with Critical Elements ⚡️; navigation to another product pushes history. Reload, copied links and Back/Forward restore state. Camera moves persist on move-end, with bounds/finite-number validation. Existing north-up, flat map needs no bearing/pitch state.

CnecPage already supports parent-owned selection but its current URL adapter does not persist camera. Add a small camera input/change contract through the shared map boundary. Restore once on entry or navigation; table clicks must never refit or recreate it. Preserve current stale-result protection and visible loading/errors; reuse cached day/interval queries. Avoid unrelated map renders for table-only filters.
